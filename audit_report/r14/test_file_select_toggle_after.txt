test_file_select_toggle.py - the one failure this round introduced, repaired
===========================================================================

The round-14 fix that gave each co-loading action name one owner per page
replaced an assignment the file pinned by its exact text:

    window.toggleAllFilesSelection = fileSelection.toggleAllFilesSelection;
  -> window.toggleAllFilesSelectionShared = fileSelection.toggleAllFilesSelection;
     (the files list page now publishes the unsuffixed name itself)

Which side was wrong
--------------------
The product behaviour is correct and was left alone: the files list page owns
`toggleAllFilesSelection` and delegates to FileManagement; the shared module
export carries the suffix; and the FMAS control in
static/js/modules/views/file-view.js names the suffixed copy explicitly
(`data-on-click="toggleAllFilesSelectionShared?.()"`). The stale side was the
test, which asserted the text of one assignment rather than the ownership rule
it was protecting.

The repair asserts the rule, not the text, and is strictly stronger:

  * the suffixed export exists;
  * `window.toggleAllFilesSelection = ` does NOT appear in the manager (an
    assignment there is exactly the collision the round fixed);
  * the control that consumes the shared copy names it explicitly, so the
    suffix cannot silently become a dead button.
