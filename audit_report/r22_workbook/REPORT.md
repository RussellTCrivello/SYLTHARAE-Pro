## Open defect found while wiring this (DEFECT-OPEN: scheduling)

The scheduling subsystem is declared in `services/scheduling/scheduler.py`
but cannot run, in three separate ways:

| # | the gap | evidence |
|---|---|---|
| 1 | `apps/web/app.py` imports `Scheduler`; the module defines `ScheduleRunner` | the app logs `Job scheduler not started: ImportError: cannot import name 'Scheduler'` on every start |
| 2 | `ScheduleRunner` expects a store object with `list_enabled`/`get`/`get_user`/`disable`; `services/scheduling/store.py` is a set of functions | no class with those names exists in the tree |
| 3 | every fire called `JobManager.enqueue`, which did not exist | **fixed** in this round: `JobManager.enqueue` now exists, and `tests/unit/test_scheduler_contract.py` fails if the scheduler calls a method the manager lacks |

Until (1) and (2) are repaired, the scheduled form of the sync does not run;
startup reconciliation, the API and `--watch` do. The repair is a small,
self-contained piece of work - an adapter over the existing store
functions, plus a `get_instance`/`fire_now` on the runner so
`POST /api/schedules/<id>/run_now` stops answering 503 - but it is not part
of the workbook's mandate, and half-wiring it would be worse than leaving
it declared and reported.

## Reproducing

```bash
python3 tools/i18n/sync_taxonomy.py --check      # rules and ownership decisions
python3 tools/i18n/sync_taxonomy.py              # planned changes, writes nothing

python3 tools/i18n/sync_taxonomy.py --apply --auto-rename   # treat a renamed sheet as a rename
```
