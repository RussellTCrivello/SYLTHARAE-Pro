**What this round changed.** Four defects were found and fixed with tests, each of which had been mis-reported as a reader limitation:

1. *The Word backfill lost repeated paragraphs.* `Other/testWORD_template.dotx` stored one of the five "Click here to enter text" placeholders the package contains, because coverage was a plain membership test on a haystack that had been normalised into a single line. It scored 0.839 and was recorded as a traversal gap. It now scores 1.000, as does `testWORD_2006ml.docx` (0.986).
2. *Encrypted Office files were reported as corrupt.* Eleven OOXML files are CFB containers with `EncryptionInfo`/`EncryptedPackage`; openpyxl and python-pptx answered "File is not a zip file" and "Package not found". Three of them had been recorded as silently empty. They now report that they are encrypted and which parts are unreadable.
3. *The audit harness could not finish a corpus, and blamed the reader when it ran out of memory.* Three previous passes ended at 604/698 with no traceback. Each file now runs in a child process with a wall-clock timeout and a 2 GiB address-space cap, and the run completed 698/698. The one file reported `ERROR MemoryError` (`Spreadsheets/testRecordSizeExceeded.xlsx`) turned out to be a harness failure, not a reader failure: the reader extracts 10,000,085 characters in 55 s, and it was the audit's own bookkeeping - 249,990 unit dicts and a token Counter over 10 MB of oracle text - that exhausted the child. Units are capped at 2,000 (the true total is kept), the oracle is scored on a 2 M-character prefix when a file is larger (recorded as `recall_scope`), and the reader's content is released before scoring. That file now scores COMPLETE at recall 1.0 against the prefix.
4. *A capped spreadsheet read was indistinguishable from a complete one.* The cell cap works (F-11), but neither `truncated` nor `cells_read` reached `extraction_provenance`; both now do, aggregated across sheets, so after ingestion a capped sheet still says it was capped.

**Main failure categories (measured, 52 ERROR).** Environment: 8 video files plus WMA/M4A need an `ffmpeg` binary that is not installed (F-29). Deliberate refusal with a stated reason: 11 archives (encrypted, corrupt central directory, or path traversal - the reader refuses `../../..` members, which is correct) and 8 encrypted Office files, now reported as encrypted rather than corrupt. Unsupported formats with no reader: PSD (3), AVIF (2), EXE (3), `.dmg`/`.dng` (2), `.numbers` (2), one `.pages`. Library limits: `.xlsb` (pyxlsb) and two non-OLE `.doc` files. ## 2. Method, thresholds and status taxonomy

The pipeline is called exactly as production calls it: `FileReaderService.read_file({path, extension})` for routing and the reader, then `StoragePipeline._extract_text_from_content()` on the reader's result - the same function that decides what is stored. Text that a reader returns but that never reaches that function is counted as loss, because it is loss.

| Verdict | Rule |
|---|---|
| COMPLETE | independent oracle exists and token recall >= 0.995 |
| NEAR-COMPLETE | 0.95 <= recall < 0.995 |
| PARTIAL | 0.75 <= recall < 0.95 |
| INCOMPLETE | recall < 0.75 |
| ERROR | the reader returned an error, the storage text builder failed, or the child process crashed; the stage that failed is named on the record |
| TIMEOUT | no record from the child process within 180 s; the child is killed and the record says so (a C-level loop cannot be interrupted in-process, which is why the timeout is enforced on a child) |
| UNVERIFIABLE | oracle empty AND stored text came from OCR (proxies recorded) |
| OK-NO-ORACLE | oracle empty AND stored text exists but is not from OCR |
| EMPTY-PLAUSIBLE | oracle empty AND nothing stored |
| EMPTY-AGREED | oracle present but empty AND nothing stored |

Recall is token recall against an independent oracle: the container's raw parts parsed with a real XML parser (OOWML, ODF), a second library (openpyxl, xlrd, PyMuPDF), or byte inspection for plain text. Both sides are normalised identically — ligatures, soft hyphens, NBSP and zero-width characters, line-break hyphenation. Character ratios are reported for information only; they reward whitespace.

The path a file takes, and where each stage can lose text:

| stage | function | decides | can lose |
|---|---|---|---|
| discovery | `Path.rglob` / job import | nothing | unreadable paths, permission errors (recorded by the job, not here) |
| detection | `core.detect_binanry_utils.sniff_file_type`, `detect_file_type_with_confidence` | the content type | a two-byte signature can beat a correct name, a ZIP can hide its own kind |
| routing | `FileReaderService.resolve_reader_for_file` | reader + effective extension | a valid document sent to a generic reader (archive, remaining) |
| read | `reader_file/readers/*.read_file` | the reader's result dict | text the library does not model, text in a part it never opens |
| structure | `pdf_layout.page_model`, `_docx_cover_remaining`, `_pptx_cover_remaining`, `_odf_block_text` | order, blocks, backfill | reading order, cross-block hyphenation, duplicated fallback branches |
| storage boundary | `StoragePipeline._extract_text_from_content` | which result keys become searchable text | any key that function does not know: read-but-never-persisted |
| persistence | `ContentDBService` | rows, status, provenance | truncation, duplication (checked by the integrity runs) |

The storage boundary is the one to keep in view: a reader can return perfect structures and still lose them. `_extract_text_from_content` is the single function that decides what is searchable, so every new reader key must be checked against it - `forensic_text` is joined there, `sheet_names` is not, page `blocks` are not (they are stored structurally, per artifact).

## 10. Integrity and performance

**Isolation (measured).** Every record in this run carries `isolated: true`, and `peak_rss_kb` is the child process's own high-water mark (`ru_maxrss`), not the harness's running maximum. The heaviest file measured 796 MiB (an OCR page); the median is under 100 MiB. No file hit the 2 GiB address-space cap and no file hit the 180 s wall-clock timeout, but both paths are exercised by tests with stub children (`tests/unit/test_audit_isolation.py`), because an untested failure path is a claim, not a control.

**Resume and interruption (measured).** `tests/unit/test_audit_resume.py` kills a run mid-flight and asserts that every line already written parses as JSON, that `--resume` adds only the missing files, and that no path appears twice. The whole-corpus run in this round was itself resumed after a deliberate stop, and the archive ended with exactly 698 records for 698 corpus files.

**Storage boundary (measured).** `StoragePipeline._extract_text_from_content` consumes 49 content keys, read from its syntax tree rather than from a hand-kept list (`storage_consumed_keys()`); the per-key table in section 10a is computed from the records. A reader key that is outside that set is content the pipeline discards, and the table separates instrumentation from loss by name.

**Idempotency and corpus safety.** The audit reads the corpus and never writes to it; hashes are recomputed per run (`sha256` in every record) and the round-17 baseline and final runs are compared record by record in section 9. Destructive probes (interruption) run against generated files in a temporary directory, never against `test-doc/`.

## 12. Final completeness assessment

**Demonstrably correct (measured).** 328 of 336 oracle-scored files are COMPLETE at token recall >= 0.995, and the mean is 0.9991. The families with the strongest evidence are plain text and HTML (every legacy code page and every charset trap in the corpus now decodes at 1.000), Office (the last two Word residuals closed this round, and spreadsheets now read cell comments without a second walk of the grid, which is what made the 250,000-cell workbook complete) and PDF (all pages with a readable layer, plus OCR provenance for scans).

**Incomplete but measured.** Four ODF files sit between 0.943 and 0.990, and the residuals are named: tracked-change author/date metadata (F-28), and one 9,347-token French document where 269 tokens are missing - not yet diagnosed beyond the sample, which is why it stays a number rather than a claim. One presentation at 0.977 and one spreadsheet at 0.995 are likewise open.

**Unsupported (recorded, not silent).** PSD, AVIF, EXE, DMG, DNG, .numbers and .pages have no reader; each ERROR record names the reason. Archives that are encrypted, corrupt or contain traversal paths are refused with the specific member named - refusal is the correct outcome, not loss.

**Silently ignored (no longer).** Before this round, encrypted OOXML and encrypted PDFs produced empty or corrupt-sounding results. They now state that they need a password.

**Unknown, and what would resolve it.** (1) OCR content: 20 files are UNVERIFIABLE; resolving them needs either a second engine's agreement or a human transcription of one page per file. (2) Video and part of audio: nothing is extracted because ffmpeg is absent; resolving needs an ffmpeg binary, after which the same harness measures them. (3) The `.xlsb`, iWork and non-OLE `.doc` cases would move from ERROR to measured if a decoder existed or a LibreOffice binary were present - both recorded in the backlog.
