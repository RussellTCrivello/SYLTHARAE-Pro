# Round 17 — the audit runs every file in its own process, and four reader defects found by it

Everything in `REPORT.md` is generated from `archive/records.jsonl` (the Phase‑1
baseline) and `final/records.jsonl` (the Phase‑7 re‑run after the fixes) by
`tools/audit/build_audit_report.py`, with the prose register in
`tools/audit/registers/r17.json`. `DIFF.md` is generated by
`tools/audit/diff_runs.py` and is the baseline‑versus‑final comparison.

## Reproducing

```bash
# one command: audit the corpus, then print the report command
PYTHON=/tmp/rv/bin/python tools/audit/run_audit.sh audit_report/r17/repro

# the report itself
python tools/audit/build_audit_report.py \
    --records audit_report/r17/final/records.jsonl \
    --register tools/audit/registers/r17.json \
    --out audit_report/r17

# baseline versus final
python tools/audit/diff_runs.py \
    --baseline audit_report/r17/archive/records.jsonl \
    --final    audit_report/r17/final/records.jsonl \
    --out      audit_report/r17
```

Limits used and recorded in every record: **180 s** wall clock per file and
**2048 MiB** address space per child (`--timeout`, `--memory-mb`).

## What changed in the harness

* **Isolation** — one child process per file, `RLIMIT_AS` cap, wall-clock kill; a
  hang, a crash or a memory kill becomes a record instead of a lost run. Three
  earlier passes had all died at 604/698 with no traceback.
* **Per-file memory is real** — `peak_rss_kb` is the child's own `ru_maxrss`
  (median 48 MiB, max 1532 MiB), not the harness's running maximum.
* **The archive is bounded** — units capped at 2 000 (`units_total` kept), the
  oracle scored on a 2 M-character prefix for large files (`recall_scope`), the
  reader's content released before scoring.
* **Failure attribution** — the record names the stage: `storage_error` for the
  text builder, `oracle_error` for the comparison, `memory_limited` for a kill.
* **Restartable** — `--resume`; tested by killing a run mid‑flight.

## Caveats, stated as such

* **Measured:** the 20 UNVERIFIABLE files are OCR; there is no independent
  oracle for a recognition, so only coverage and confidence proxies are reported.
* **Measured:** video (8) and two audio files fail because no `ffmpeg` binary
  exists in this image. That is an environment verdict, not a reader verdict.
* **Hypothesis:** the 0.971 ODF (`testODT-TIKA-6000.odt`, 269 of 9,347 tokens)
  and 0.977 PPTX residuals are single traversal gaps; neither has been reproduced
  as a minimal fixture yet, so both stay numbers rather than claims.
* **Not covered here:** database-level idempotency (no PostgreSQL server in this
  image). Extraction-level idempotency is tested
  (`tests/unit/test_extraction_idempotency.py`).
